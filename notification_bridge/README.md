# Центр уведомлений: паттерн Bridge (Мост)

Flask + SQLite + HTML/CSS. Полный CRUD для таблицы `notifications`.

## Запуск

```
pip install -r requirements.txt
python app.py
```

Открыть http://127.0.0.1:5000. Файл `database.db` уже создан и содержит 4 тестовые записи.
Если его удалить, он создастся заново при запуске.

## Структура

```
app.py                  маршруты Flask, валидация
db.py                   подключение к SQLite, создание таблицы, тестовые данные
database.db             база данных
patterns/bridge.py      реализация паттерна Bridge
templates/              index, add, edit, detail, pattern, error, base, _form
static/style.css        стили
```

## Маршруты

| Операция | Маршрут |
|---|---|
| Read (список, фильтры) | `GET /` |
| Read (одна запись) | `GET /notification/<id>` |
| Create | `GET, POST /add` |
| Update | `GET, POST /edit/<id>` |
| Delete | `POST /delete/<id>` |
| Демонстрация паттерна | `GET, POST /pattern` |

## Краткое объяснение паттерна

**Bridge** разделяет абстракцию и реализацию на две независимые иерархии, которые связаны композицией.

- **Абстракция:** `Notification` и наследники `NormalNotification`, `ImportantNotification`, `EmergencyNotification`.
  Они решают, как оформить текст (заголовок, дополнение, число попыток).
- **Реализация:** `Channel` и наследники `EmailChannel`, `SMSChannel`, `TelegramChannel`.
  Они решают, как доставить текст (тема письма, обрезка до 160 символов для SMS, разметка для Telegram).
- **Мост:** поле `self.channel` в `Notification`. Приоритет не знает, какой именно канал ему передали,
  и просто вызывает `self.channel.deliver(...)`.
- **Сборка:** `create_notification(тип, приоритет)` создаёт нужную пару. Вызывается в `app.py`
  на странице уведомления и на странице `/pattern`.

## Ответы на вопросы защиты

1. **Какую проблему решает приложение?** Хранит уведомления и показывает, как они будут доставлены
   в зависимости от типа и приоритета.
2. **Какой паттерн?** Bridge (структурный).
3. **Почему он?** Тип и приоритет меняются независимо: любая из 3 типов сочетается с любым из 3 приоритетов.
4. **Где в коде?** `patterns/bridge.py`: классы `Notification`, `Channel` и их наследники, функция
   `create_notification`. Использование: `detail()` и `pattern()` в `app.py`.
5. **Как работает CRUD?** Маршруты в таблице выше. Данные проверяет `validate()` (длина текста 3-500,
   тип и приоритет только из списка), запросы к SQLite параметризованы, удаление только через POST.
6. **Что будет без паттерна?** Понадобится класс на каждую пару (3 x 3 = 9), а с каждым новым каналом
   или приоритетом их станет ещё больше. С мостом достаточно 3 + 3, а новый вариант добавляется одним классом
   и одной строкой в `CHANNELS` или `PRIORITIES`.
